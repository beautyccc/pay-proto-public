| 张无忌（需求覆盖） | 只把本文当界面口径参考；MP/AD 全量覆盖以他的 `docs/req-coverage.md` 为准 |

### 0.2 本文覆盖什么、不覆盖什么

覆盖：v0.1 已有的 17 屏（代理端 11 屏 + 后台 6 页），以及 v0.2 新增 5 页（代理树、码牌出图、提现审批、交易查询、门店列表/新增编辑）。合计 22 屏。其中 M13 交易查询、M14 门店为 v1.1 增补，页规格见 §7.4 / §7.5。

不覆盖：下级代理（代理端）、展业支持、通知公告、奖励引擎、码牌模板管理、系统管理等尚未成页的 MP/AD 条目。它们不在 v0.2 的实现范围；本文只在导航契约里说明「未开放入口」怎么表现，避免误跳。门店管理与交易查询已移入 v0.2 覆盖，不再属于「未开放」。

### 0.3 三条硬规则

1. **一个屏只有一个主操作**。主按钮视觉权重最高；次要操作降级为描边按钮、文字按钮或链接。
2. **金额和状态不能有第二种读法**。金额一律整数「分」换算展示，状态一律「文字 + 颜色 + 图标」三重表达。
3. **每个页面必须能回答：加载中、没有数据、出错、被驳回、被停用，分别长什么样。** 缺一个都算未完成。

## 1. 设计方向

### 1.1 目标用户

| 角色 | 场景 | 设计含义 |
|---|---|---|
| 代理（服务商本部 + n 级代理） | 在商户店里、路上、手机上操作；网络可能只有 4G；一次要办完一件事 | 大按钮、短路径、少层级；金额和状态第一眼可读；失败能重试 |
| 平台运营 | 桌面端连续使用数小时；同时看列表、审提现、处理差错 | 高信息密度但不拥挤；表格可扫读；危险操作有二次确认和留痕 |

### 1.2 每屏动手前必须回答的三个问题

| 问题 | 不合格的表现 | 本文的答案在哪 |
|---|---|---|
| 目标用户是谁 | 「所有人」 | §5 每屏的「用户 / 唯一目标」 |
| 这个页面唯一目标是什么 | 一屏放三个同等重要的按钮 | §5 每屏的「唯一主操作」 |
| 成功和失败各长什么样 | 只画了成功态 | §6 六态矩阵 + §9 文案 |

### 1.3 美学方向：工具型账本感

不是营销页，不做插画和装饰性大图。整体是「安静的账本」：中性灰底、白色卡片、一个品牌绿、金额用等宽数字、状态用低饱和底色。信息密度可以高，但层级必须清楚。允许的视觉重点只有两个：**金额 hero** 和 **当前主操作**。除这两个地方外不使用大面积渐变。

### 1.4 五条设计原则

1. **先可信，再好看。** 商户名、金额、订单号、当前状态必须同时出现；不可逆操作必须二次确认。
2. **一屏一主操作。** 主按钮最多一个；「新增」和「提现」不能在同一屏争抢。
3. **状态是一等公民。** 默认、加载、空、错误、驳回、停用六态都要定义，不能只做默认。
4. **异常必须有出路。** 每个错误至少给「重试 / 查询进度 / 联系上级」之一，不能是死胡同。
5. **规范必须可执行。** 颜色、字号、间距、圆角、文案都给到具体值；不写「参考某某产品」。

### 1.5 与通用视觉规范的三处覆盖（明确说明，避免实现时纠结）

| 项 | 本文选择 | 理由 |
|---|---|---|
| 字体 | 系统字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` | 小程序原生观感；中文屏显最稳；零字体加载；无付费授权。**覆盖**通用规范里「不用系统字体」的默认建议 |
| 品牌绿 | 保留微信绿 `#07C160` 做品牌识别，但**不用它承载白色文字**；按钮/文字用 `#067A43` | 白字在 `#07C160` 上对比度只有 2.38:1，不满足可读性；不能为了品牌牺牲阅读 |
| 图标 | 内联 SVG（Lucide 线性图标，ISC 许可），线宽 1.75，`currentColor` | 跨端一致、可控、无外部依赖；**禁止 emoji 当图标** |

### 2.2 语义色与状态词

一个状态必须同时有：**颜色 + 文字 + 图标**。禁止只靠颜色区分。

| 语义 | 底色 | 文字 | 图标（Lucide） | 典型状态 |
|---|---|---|---|---|
| 成功 / 已通过 | `--success-soft` | `--success` | `check-circle` | 已通过、已签约、已到账、正常 |
| 信息 / 进行中 | `--info-soft` | `--info` | `loader` 或 `info` | 处理中、审批中、待打款、试运行标签 |
| 警告 / 待处理 | `--warning-soft` | `--warning` | `clock` 或 `alert-triangle` | 待完善、待签约、待审批、结果未知 |
| 危险 / 失败 | `--danger-soft` | `--danger` | `x-circle` 或 `alert-circle` | 已驳回、打款失败、已停用、交易不平 |
| 中性 / 未开始 | `#F1F4F8` | `--muted` | `circle` | 未开始、未开通、已下线 |
| 禁用 | `#F3F4F6` | `--disabled-text` | `minus-circle` | 不可操作，仅视觉 |

### 2.7 动效

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| hover / 颜色变化 | 120ms | `ease-out` | 不移动布局 |
| 按钮按下 | 120ms | `ease-out` | `translateY(1px)` |
| 弹窗 / 抽屉 | 200ms | `cubic-bezier(.2,.8,.2,1)` | 遮罩淡入 + 面板上移 |
| 页面切换 | 160ms | `ease-out` | 不做横向滑动，避免误触 |
| 骨架 shimmer | 1.4s | `linear` | 循环；低对比，不抢眼 |

`prefers-reduced-motion: reduce` 时关闭 shimmer、位移动画，只保留透明度变化。

### 2.8 金额与数字格式（P0）

**存储与计算**：一律整数「分」。JS 内不做浮点累加；只在展示层除以 100。

```text
fee_cents  = min(amount_cents, round_half_up(amount_cents * 8 / 100) + 300)
net_cents  = amount_cents - fee_cents
display    = (cents / 100).toLocaleString('zh-CN', { minimumFractionDigits: 2, maximumFractionDigits: 2 })
```

说明：`8% + 3 元/笔` 是 v1.1 §15.2 待确认项，当前只作为演示常量 `FEE_RATE = 0.08`、`FEE_FIXED_CENTS = 300`；确认后只改这两个值和文案，不改页面结构。

**展示规则**：

| 场景 | 格式 | 示例 |
|---|---|---|
| hero 余额 / 交易额 | `¥` + 千分位 + 两位小数，整体同字号 | `¥1,286,430.00` |
| 表格金额 | 表头写「（元）」，单元格右对齐、两位小数、无符号 | `86,240.00` |
| 明细/到账 | `¥` + 千分位 + 两位小数 | `¥4,597.00` |
| 负数 | 减号用 `−`（U+2212），危险色仅用于冲减/亏损 | `−¥24.60` |
| 零值 | 明确写 `0.00`；不适用才用 `—` 并配说明 | `0.00` / `—` |
| 费率 | 两位小数 + `%` | `0.38%` |
| 手续费规则 | 百分比 + 固定额 + `/笔` | `8% + ¥3.00/笔` |
| 订单号 / 商户号 | 等宽数字，可复制；列表可脱敏 | `PS20261110001` |

**边界值（提现）**：

|---|---|---|---|---|

| `100.00` | 通过 | `¥11.00` | `¥89.00` | 正常试算 |
| `5,000.00` | 通过 | `¥403.00` | `¥4,597.00` | 正常试算 |
| `20,000.00` | 通过 | `¥1,603.00` | `¥18,397.00` | 正常试算 |
| `20,000.01` | 拦截 | — | — | 「单笔最高提现 ¥20,000.00」 |

| 字段 | 列表 | 详情 |
|---|---|---|

| 银行卡 | `**** **** **** 8899` | 同列表 |
| 商户号 | `M8832 **** 0912` | 完整显示 + 复制 |
| 订单号 | 完整 | 完整 + 复制 |

**时间**：统一北京时间（`Asia/Shanghai`）。详情用 `YYYY-MM-DD HH:mm`；列表用 `MM-DD HH:mm`；账期用 `YYYY-MM`。不写「昨天」「刚刚」，避免跨时区/跨天误读。

### 4.3 关键组件细则

#### C01 按钮

| 变体 | 用途 | 默认 | Hover | Pressed | 禁用 |
|---|---|---|---|---|---|
| Primary | 唯一主操作 | `--brand-strong` 底、白字 | `--brand-pressed` | 再深 + 1px 下移 | 灰底、灰字、无阴影 |
| Secondary | 次要操作 | 白底、`--border` 边、`--ink` 字 | 边框 `--border-strong` | `--surface-2` 底 | 灰底、灰字 |
| Ghost | 第三级、返回 | 透明底、`--brand-strong` 字 | `--brand-tint` 底 | 同 hover | 灰字 |
| Danger | 停用、驳回 | `--danger` 底、白字 | `#991B1B` | 再深 | 灰底 |
| Text | 表格行内、全部提现 | 无底、`--brand-strong` 字 | 下划线 | 同 hover | 灰字 |

- 尺寸：`lg` 48 / `md` 40 / `sm` 32；移动端主按钮全宽；后台主按钮自适应宽度。
- 文案：动词 + 结果。`提交提现申请`、`确认停用商户`、`重新提交资料`；禁止单独写 `确定`、`提交`、`保存`。
- Loading：按钮宽度锁定，文案换 `提交中…`，左侧 16px spinner；`aria-busy="true"`；不可重复点击。
- 图标按钮：移动端 44×44，后台 32×32；必须有 `aria-label`。
- 一屏只能有一个 Primary；出现两个即验收不通过。

#### C02 输入与表单校验

| 状态 | 边框 | 辅助信息 | 行为 |
|---|---|---|---|
| 默认 | `--border` | 可无 | 点击聚焦 |
| Focus | `--focus` + 3px 12% ring | 无 | 键盘弹出，字段滚入可视区 |
| 已填 | `--border` | 可显示字符数 | 显示清空按钮（金额除外） |
| 错误 | `--danger-icon` | 下方红字 + `alert-circle` 12px | 保留输入；提交时滚到第一个错误 |
| 只读 | `--border` + `--surface-2` 底 | 「不可修改」说明 | 不可聚焦 |
| 禁用 | `#F3F4F6` 底 | 原因说明 | `aria-disabled` |
| Loading | 同默认 | 右侧 spinner | 不可编辑（仅远程校验） |

- 每个输入必须有可见 `<label>`，不能用 placeholder 代替。
- 必填用红色 `*`，并在表单顶部说明「带 * 为必填」。
- 错误文案格式：发生了什么 + 为什么 + 怎么办。例：「身份证号与姓名不匹配。请核对后重新填写。」
- 提交失败时，顶部显示错误摘要（几条错误 + 锚点），并保留所有已填内容。
- 金额输入：`inputmode="decimal"`；只允许数字与一个小数点；最多两位小数；失焦格式化千分位。

#### C08 状态 chip

- 结构：12px 图标 + 11/600 文字 + 3×8 内边距 + 6 圆角。
- 六种语义见 §2.2；同一页面同一状态必须用同一种 chip，不允许「报备中」有时黄有时蓝。
- 长状态（如「报备处理中，预计 11-12」）不要塞进 chip；chip 只放短词，解释放旁边说明或详情。
- 颜色不是唯一线索：旁边必须有文字；色盲用户也能读。

#### C17 三态看板（进件 / 签约 / 报备）

| 子状态 | 底色 | 文字色 | 图标 | 文案示例 |
|---|---|---|---|---|
| 未开始 | 中性 `#F1F4F8` | `--muted` | `circle` | 未开始 |
| 处理中 | `--warning-soft` | `--warning` | `clock` | 进件中 / 报备中 |
| 已通过 | `--success-soft` | `--success` | `check-circle` | 已通过 / 已签约 |
| 已驳回 | `--danger-soft` | `--danger` | `x-circle` | 已驳回 |
| 已停用 | `#F3F4F6` | `--disabled-text` | `minus-circle` | 已停用 |

- 三态必须**独立展示**，允许「进件已通过、签约待扫码、报备未开始」这种不同步；页面需有一句「以通道回调为准，三态可能不同步」。
- 一个商户多通道时，先选通道（Tabs 或下拉），再显示该通道的三态；不能把多个通道的状态混在一个看板里。
- 每个状态块包含：状态名（11px）、状态值（13/650）、时间/预计时间（11px）、驳回原因入口（仅驳回态）。
- 移动端 359 以下改为 3 行纵向，左侧状态名、右侧状态值，避免三列挤压。
- 后台同上，另加时间线展示操作轨迹。

#### C19 / C20 金额展示与提现试算

- 金额 hero：`¥` 18/600 + 数字 28/700 + 小数 28/700（**不要把小数字号缩小**，避免误读）；整体右对齐或左对齐固定，不居中漂浮。
- 列表金额：16/700，右对齐，等宽数字；表格内 13/600。
- 提现输入：`¥` 22/600 + 输入 30/700；下边框 1px；聚焦时底边变 `--brand`；不套大圆角盒子（减少「已支付」错觉）。
- 试算区：三行「提现金额 / 手续费 / 预计到账」，到账行加粗 16/700 `--brand-strong`；手续费行带「费率待确认」chip；下方一行小字公式。

**布局**：导航栏「码牌生成」→ 步骤条 → 商户/门店 → 模板 → 预览 → 操作 → 生成记录。

**区块**

3. 模板横滑：3 张卡；每张含缩略预览、模板名 13/600、尺寸 11；选中 1.5px `--brand` 边 + 勾。
4. 预览区：280×360 白卡；商户名 14/600（最多 2 行）；QR 200×200；支付方式图标 24；底部「演示码」水印（仅原型）。

| 模板 | 成品尺寸 | 预览比例 | 用途 | 备注 |

| 桌贴 | 90 mm 圆 | 1:1 | 餐桌/吧台 | 圆形裁切线，QR 居中 |
| 贴纸 | 70 × 70 mm | 1:1 | 门贴/窗口 | 最小字号不低于 9pt |

**生成与下载规则**
- QR 静区 ≥ 4 个模块（预览按 16px）；不拉伸、不裁切、不加滤镜。
- PNG 长边 ≥ 2000px（300dpi 等效）；文件名 `码牌_商户名_模板_YYYYMMDD.png`。
- 保存到相册需权限；拒绝时弹窗「需要相册权限才能保存」+ `去设置` + `下载 PNG` 备选。原型环境无法写入相册时，按钮提示「演示环境请使用下载 PNG」，不能假装保存成功。
- 生成中按钮 loading，预览区骨架；失败保留已选商户/模板，给 `重新生成`。
- 演示二维码用静态占位图/占位 SVG，必须带「演示码」水印；生产替换为真实码值。

## 8. 关键流程交互

### 8.1 注册 → 实名 → 审核 → 驳回重提

**正常路径**

1. 启动页点「登录」→ 登录页点「我有邀请码，去注册」。
2. 输入/扫描邀请码；校验成功显示上级「云启支付 · 华东大区」；失败阻断，不能继续填表。
3. 填写主体信息与结算账户；上传身份证正反面、银行卡照；勾选两份协议。
4. 点「提交审核」：按钮 loading，防重复；成功进「审核中」，显示预计 1 个工作日。
5. 审核中可刷新；通过后自动进首页；驳回则显示原因与「重新提交资料」。
6. 重提：表单预填，只允许改被驳回项；提交后回到审核中。

**异常分支**

| 分支 | 触发 | 界面 | 用户下一步 |
|---|---|---|---|
| 邀请码无效 | 码不存在/过期/已用完 | 输入框红字「邀请码无效或已过期，请向你的上级重新获取」 | 重输或联系上级 |
| 手机号已注册 | 提交时校验 | 「该手机号已注册。请直接登录，或使用其他手机号」 | 去登录 |

### 8.2 商户进件 → 三态 → 驳回重提

**正常路径**

1. 商户列表点「新增」→ 进件页。
2. 选通道（银盛/拉卡拉/易生；支付宝大额暂停）；选商户类型（个人小微/个体工商户）。
3. 填主体资料、结算账户；上传门头照/证件/银行卡；手写签名；勾选协议。
4. 点「提交进件」：loading；成功进商户详情，三态初始为「进件中 / 未开始 / 未开始」。
5. 进件通过后变「已通过」；商户扫码签约后「已签约」；报备由通道代办，显示「报备中」→「已通过」。
6. 三态允许不同步；页面始终显示「以通道回调为准」。

**异常分支**

| 分支 | 触发 | 界面 | 用户下一步 |
|---|---|---|---|
| 通道暂停新增 | 选中的通道被运营暂停 | 弹窗「该通道已暂停新增，请选择其他通道」；暂停卡禁用 | 换通道 |
| 商户名重复 | 同通道已存在 | 「该商户已存在。请勿重复进件，可在商户列表查看」 | 去列表 |
| 身份证过期 | 有效期早于今天 | 「身份证已过期，请更新后重新提交」 | 改有效期/证件 |

| 签名/协议缺失 | 提交校验 | 顶部错误摘要 + 滚到签名区 | 补签名/勾选 |
| 提交结果未知 | 等待过长 | 详情页「进件结果确认中」+ 查询；不显示成功 | 查询；不重复提交 |

| 报备驳回 | 微信/支付宝驳回 | 同上；其他两态保留 | 重提报备 |
| 商户停用 | 风控冻结 | 灰条 + 原因/时间；不可新增交易 | 联系上级/运营 |

### 8.3 提现 → 审批 → 代付 → 结果

**状态流转**

| 阶段 | 页面 | 状态词 | 用户看到 | 可做 |
|---|---|---|---|---|
| 提交前 | M10 | — | 金额、手续费、到账、账户 | 改金额/账户 |
| 已提交 | M10 记录 | 审批中 | 单号、提交时间、预计 T+1 | 查询进度、查看记录 |
| 运营已接单 | A08 / M10 | 审批中 | 审批人/时间（可选） | 等待 |
| 审批通过 | A08 / M10 | 待打款 → 打款中 | 预计到账时间 | 等待 |
| 成功 | M10 | 已到账 | 到账时间、到账金额 | 查看记录 |
| 失败 | M10 | 打款失败 | 失败原因、重试/退回余额 | 重试或联系客服 |
| 驳回 | M10 | 已驳回 | 驳回原因、操作人/时间 | 修改后重新发起 |
| 未知 | M10 | 结果未知 | 「请勿重复提交」+ 查询 | 查询进度 |

**正常路径**

1. 收益页选科目 → 提现；或提现页切换科目。
2. 输入金额；实时试算手续费与到账；校验最低/最高/余额。
3. 选收款账户（对私/对公）；对公补齐企业信息。
4. 点「提交提现申请」→ 确认抽屉复核金额/手续费/到账/账户。
5. 点「确认提交 ¥5,000.00」→ loading；成功 toast「提现申请已提交，等待运营审批」；记录出现「审批中」并生成提现单号。
6. 运营在 A08 打开**同一单号**通过 → 通道代付 → 成功/失败回填；代理在记录里看到最终状态。

**MP-86 最小闭环（v0.2 必做，演示数据）**

1. M10 提交成功 → 生成一张提现单，状态「审批中」，单号规则 `WD + yyyyMMdd + 4 位序号`。
2. 代理端 M10「提现记录」立即出现该单：单号、金额、科目、提交时间、状态「审批中」。
3. 后台 A08 `#p-withdrawals` 待审批 tab 出现同一单号；金额、科目、账户与 M10 完全一致（两端不允许对不上）。
4. 运营在 A08 `通过并打款` 或 `驳回申请`（驳回原因必填 ≥ 5 字）→ 状态回写为「打款中 / 已到账」或「已驳回」。
5. 代理端记录刷新后看到同一状态与驳回原因；全程不接真实资金、不产生真实代付。
- 断点要求：任一端刷新后状态一致；重复提交只生成 1 张单；A08 通过 / 驳回后同一单不可重复操作。

**异常分支（必须全部有界面）**

| 分支 | 触发 | 界面 | 用户下一步 |
|---|---|---|---|
| 低于最低 | 金额 < 100 | 输入框下「单笔最低提现 ¥100.00」；按钮不提交 | 改金额 |
| 高于最高 | 金额 > 20,000 | 「单笔最高提现 ¥20,000.00，请分笔提交」 | 改金额/分笔 |
| 余额不足 | 金额 > 科目余额 | 「超出可提现余额，当前可提现 ¥62,180.20」 | 改金额/全部提现 |
| 未绑卡 | 无结算卡 | 账户区「请先绑定结算卡」+ 去绑定；提交禁用 | 绑卡 |
| 断网 | 提交时无网络 | 横幅「网络连接中断，提现申请未提交」+ 重试；保留金额 | 重试 |
| 重复提交 | 连续点击/返回再提交 | 按钮 loading + disabled；提示「这笔提现正在处理中，请勿重复提交」 | 查看记录 |
| 结果未知 | 请求等待过长 | 黄色横幅 + 单号 +「查询进度」；禁止再次提交 | 查询，不重提 |
| 审批驳回 | 运营驳回 | 记录「已驳回」+ 原因；顶部红条 +「重新发起」 | 改资料/金额后重提 |
| 打款失败 | 通道失败 | 记录「打款失败」+ 原因 +「重试」/「退回余额」 | 重试或联系客服 |
| 账号停用 | 账号冻结 | 全页灰条 + 提交禁用；仅记录可查 | 联系上级 |
| 提现关闭 | 功能维护 | 按钮禁用 +「提现功能维护中，预计 …恢复」 | 稍后再试 |

### 8.4 码牌生成 → 预览 → 下载

1. 首页「终端管理」或商户详情「查看收款码」→ M12；带入商户。
2. 选商户/门店；只允许正常状态；驳回/停用置灰并说明。
3. 选模板（立牌/桌贴/贴纸）；预览即时更新。
4. 点「保存到相册」或「下载 PNG」；生成中 loading；成功后 toast「已保存到相册」/「PNG 已下载」。
5. 生成记录可再次生成/下载。

**异常**：无商户 → 去新增；无模板 → 联系运营；生成失败 → 保留选择 + 重试；相册权限拒绝 → 去设置或下载 PNG；商户停用 → 禁止生成。

### 8.5 代理树：调费率 / 停用 / 调整关系

**调费率**

1. A07 选中代理 → 费率 tab → 调整费率。
2. 弹窗显示成本价（只读）、当前报价、新报价、生效时间。
3. 输入新报价；实时校验：≥ 成本价；若该代理有下级，≤ 下级最低报价。
4. 保存 → 成功 toast + 操作日志；失败留在弹窗，显示具体原因。

**停用**

1. 详情 → 停用 → 原因必填 → 确认。
2. 成功后节点灰显、状态「已停用」；该代理不能新增商户；存量分润照常结算。

**调整关系**

1. 详情 → 调整关系 → 选新上级 → 生效日期 → 提交。
2. 状态「变更待审批」；审批通过后树刷新，并在日志里记录前后上级。
3. 不允许选自己或自己的下级；错误就地提示。

### 8.6 对账差错处理（后台）

1. A06 拉取对账单；显示交易/分账/代付三路结果。
2. 差错池选一笔 → 处理抽屉：系统金额 vs 通道金额、差额、可能原因。
3. 选处理方式：确认差异 / 挂账 / 驳回；备注必填；提交。
4. 成功后状态「已核实」/「已驳回」；差错记录不进入分润，处理完成后由日终任务补算。

### 8.7 交易查询 → 详情

1. 首页「交易查询」→ M13；默认近 7 天，列表 10 条。
2. 展开筛选，选日期区间、商户、门店、通道、支付方式、状态；点「查询」→ 列表与汇总条同时更新。
3. 点某行 → 详情抽屉：金额、状态、订单号、通道流水号、手续费、分润明细。
4. 核对分润合计；需要留证时点「复制订单号」/「复制通道流水号」。
5. 关闭抽屉 → 回到原列表位置，筛选条件不丢。

**异常分支**

| 分支 | 触发 | 界面 | 用户下一步 |
|---|---|---|---|
| 日期非法 | 开始晚于结束 | 字段下红字，查询不执行 | 改日期 |
| 筛选无结果 | 条件过窄 | 「当前筛选没有交易」+「清除筛选」 | 清除筛选 |
| 列表加载失败 | 接口/网络 | 列表区错误 + `重试`；筛选保留 | 重试 |
| 单条缺失 | 数据不全 | 该行显示「—」，不白屏；详情提示「该笔信息不完整，请联系客服」 | 联系客服 |
| 退款/关单 | 状态非成功 | 列表 `−` 金额 + 状态 chip；详情红色说明与原因 | 查看原因 |
| 分润不平 | 合计差 > 0.01 | 详情「分润明细待核对」，禁用导出 | 联系运营 |

### 8.8 门店 → 码牌联动

1. 商户详情「门店数」→ M14；头卡显示商户与门店数。
2. `＋ 新增门店` → 填名称、地址、联系人、电话 → `保存门店`；成功回列表，新行置顶。
3. 点门店行 → 编辑预填 → 改地址 → 保存；列表同步更新。
4. 进入 M12（首页终端管理或商户详情查看收款码）→ 门店选择器选该门店 → 生成码牌。
5. 回 M14 停用该门店（原因 2–50 字）→ M12 不再可选，历史记录仍可下载并提示重新生成。

**异常分支**

| 分支 | 触发 | 界面 | 用户下一步 |
|---|---|---|---|
| 必填缺失 | 名称/地址为空 | 字段下红字 + 保存禁用 | 补填 |

| 重复点击 | 连点保存 | loading + disabled，只产生 1 条 | 等待 |
| 商户停用 | 商户状态异常 | 整页只读 + 灰条；隐藏新增 | 联系上级 |

## 10. 可访问性

### 10.1 对比度

- 正文（< 18.66px 粗体 / < 24px 常规）≥ 4.5:1；大字 ≥ 3:1；图标、边框、focus ring ≥ 3:1。
- 以下组合**禁止**用于承载信息的文字：
  - 白字 + `#07C160`（2.38:1）
  - `#8A94A6` + 白（3.06:1）
  - `#B3BBC8` + 白（1.93:1）
  - `#D97706` + 白（3.19:1）
  - `#0F9D58` + 白（3.51:1）
  - `#DC2626` + `#FDEEEE`（4.29:1，差 0.21）
- 允许的低对比场景只有：禁用控件、纯装饰线、非信息性水印；且必须同时有文字说明。

### 10.2 触控与焦点

- 移动端可点击区域 ≥ 44×44；后台 ≥ 32×32；相邻目标间距 ≥ 8。
- 键盘 focus 必须可见：2px `--focus` ring + 2px offset；不允许 `outline: none` 无替代。
- 焦点顺序与视觉顺序一致；弹窗打开后焦点进入弹窗，Esc 关闭，关闭后回到触发元素。
- 移动端底部抽屉的关闭按钮 ≥ 44×44；支持系统返回手势。

### 10.3 表单与错误

- 每个输入有可见 `<label>`，`for` 绑定；必填有 `*` 和说明。
- 错误用 `aria-describedby` 关联；`aria-invalid="true"`；提交失败把焦点移到错误摘要。
- 不用 placeholder 代替 label；placeholder 只做示例，颜色 ≥ 4.5:1（用 `#6B7280`）。
- 错误不能只变红：要有图标 + 文案 + 行动。
- 金额输入 `inputmode="decimal"`；手机号 `inputmode="numeric"`；姓名/商户名 `autocomplete` 合理设置。

### 10.4 颜色与图标

- 状态必须「文字 + 颜色 + 图标」；色盲用户只读文字也能理解。
- 图表/进度不能只靠颜色区分；加数值标签或图案。
- 图标按钮必须有 `aria-label`；装饰图标 `aria-hidden="true"`。
- 不用 emoji 当图标；不用纯字符凑图标。

### 10.5 屏幕阅读器

- 金额：`aria-label="五千元，手续费四百零三元，预计到账四千五百九十七元"` 或在旁边提供完整文本；不要只读一串数字。
- 状态 chip：`role="status"`；变化时播报「提现状态已更新为已到账」。
- Toast：`role="status" aria-live="polite"`；错误用 `role="alert"`。
- 弹窗：`role="dialog" aria-modal="true"`，标题用 `aria-labelledby`。
- 表格：`<th scope="col">`；金额列标明单位；操作链接有具体名称（「审批 PS20261110001」而不是「审批」）。
- 树：`role="tree"` / `treeitem` / `group`；`aria-expanded`、`aria-level`、`aria-selected`。

### 10.6 缩放与动效

- 200% 浏览器缩放不裁切、不出现页面级横向滚动；文字不放进图片。
- 支持系统字体放大；固定高度容器要允许内容撑开。
- `prefers-reduced-motion: reduce` 时关闭 shimmer、位移动画；保留 120ms 透明度变化。
- 不做自动播放、闪烁、连续抖动；错误不靠抖动表达。
